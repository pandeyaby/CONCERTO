# v4 harness notes (disclosures only; PREREG thresholds/arms/validity unchanged)

## 2026-10-13 — harness fixes before campaign start

1. **`run_all.sh` push after trial commit.** With `COMMIT=1`, the harness already committed each completed trial (including a one-shot `<label>b` rerun). Added `git push -u origin HEAD` after that commit so the `v4-campaign` remote branch advances after every trial, as required for this campaign run.

2. **`analyze.py` `invalid_*` trial classification.** Invalid trials are renamed to `invalid_<label>`. The previous analyzer treated any non-`p1_*` directory name as P3, so `invalid_p1_*` rows errored instead of being scored under the P1 validity/metrics path. Fixed by stripping the `invalid_` prefix before choosing `a_p1` vs `a_p3`. Verdicts still use only valid, non-`invalid_*` trials. Thresholds, arms, and the gap ≤ 10 s / duration rules are unchanged.

3. **`analyze.py` G0 → G1–G3 INCONCLUSIVE.** When `G0_informative` is false, emit `G1`/`G2`/`G3` as the string `INCONCLUSIVE` rather than omitting them or mapping a boolean to FAIL, matching PREREG v4 (“If G0 fails, G1–G3 are INCONCLUSIVE … and are not reported as PASS or FAIL”).

4. **`testbed/setup.sh` adapter path after `cd /tmp`.** `sudo bash testbed/setup.sh` prints SETUP OK but the prometheus-adapter install was a no-op: the script `cd`s to `/tmp` before `dirname $(readlink -f $0)`, so a relative `$0` no longer resolves and `helm install adapter ... || true` swallows the failure. Fixed by capturing `TESTBED_DIR` before the chdir. On this campaign host the adapter was installed manually with the same `adapter-values.yaml` before any trial; HPA custom metric `envoy_ok_rps` is required for P1.

5. **Sampler timestamps: monotonic elapsed, not `date +%s` (2026-10-13, mid-campaign).** Long agent-idle sleeps suspended the VM mid-trial. Wall-clock `date +%s` then jumped by ~1800–2400 s between consecutive samples, so the unchanged gap ≤ 10 s rule marked healthy runs invalid (`invalid_p1_p1ctl_2`, and its one-shot rerun `p1_p1ctl_2b` which was already in flight under the old sampler). Samplers now live in `sample_replicas.py` / `sample_ejected.py` and record `int(time.monotonic() - t0)` seconds since sampler start. The validity thresholds, arms, and gap ≤ 10 s rule are unchanged; only the clock basis of the sample series is corrected so suspend/NTP discontinuities are not mistaken for a broken scrape loop. A host keep-alive loop was also started to reduce further suspends. PREREG.md was not edited.

6. **Orphan `p1_ctl.py` after `p1_p1ctl_2b` (2026-10-13).** The `p1_p1ctl_2b` trial shell was reparented to PID 1 with stdout still attached to `replicas.csv` and its controller left running. That orphan kept POSTing runtime circuit-breaker caps to the shared edge admin port `127.0.0.1:30902` (namespace `v4p1`) through the whole of `p1_indep_2`. Under the pre-registered gap/duration validity rule `p1_indep_2` is valid, but its attainment (0.6935, 3 replicas) is **contaminated** relative to the static INDEP trap (compare `p1_indep_1`: 0.2631, 2 replicas). The orphan was killed at 22:22 UTC before `p1_safe_2` load; trial cleanup now `pkill`s leftover controllers/samplers. No PREREG change; report contamination in the campaign summary.
